# EstateForge 1.0.1

Release date: 17 November 2026. Bug-fix release following the first GitHub CI run.

## Fixes

- Return HTTP 503, with the existing safe response and retry guidance, when PostgreSQL is
  unreachable and Node reports a connection failure after trying both IPv6 and IPv4. Network
  failures from unrelated services retain their existing treatment.
- Set every application database connection to UTC before handing it to the pool. This prevents
  shifted timestamps and incorrect expiry checks when the server or database defaults to a
  different time zone.
- Make the seed integration test independent of database collation while preserving its checks
  of individual properties and photographs.
- Count only the connections belonging to the pool under test and wait for their removal with a
  bounded condition, preserving shutdown and no-reconnection guarantees.

## Validation

The fixes were tested locally on Windows and Linux with PostgreSQL 17, including a database with
`Europe/Madrid` as its default time zone. The local results were shared 212/212, API 2252/2252,
web 670/670 and repository scripts 60/60. Publication of this release is gated on GitHub CI
passing for the final release commit; see [GitHub Actions](https://github.com/DavidOrtegaH/estateforge/actions).

No schema change or new database migration is required by this patch. Restart the API when
upgrading so that new connections use the UTC initialization. Verification through the real Neon
pooler remains part of the deployment checks.

## Scope and remaining limitations

The source code is published under the proprietary [license](../../LICENSE), with no external
contributions accepted. Version `v1.0.0` and its history remain unchanged.

The application has not been deployed. Vercel, Neon, Vercel Blob and real AI providers remain
unvalidated. Opening the hosted service with real users' data still requires deployment checks and
the legal review of its privacy and terms drafts. Safari and physical mobile devices have not been
tested. The accepted Prisma CLI advisory exception remains unchanged. A pre-existing pg deprecation
warning in the recovery concurrency test should be reviewed before upgrading to pg 9.
