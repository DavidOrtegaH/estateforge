# EstateForge 1.0.0

Release date: 17 November 2026. First public version.

EstateForge prepares the material for real estate listings: property records, photo galleries,
listing texts, classic posters and videos composed in the browser, and a record of where each
listing is published. AI is optional and always uses the user's own provider key. See the
[changelog](../../CHANGELOG.md) for the full list of changes.

## Highlights

- Static public landing page at `/`; the application moved to `/panel`.
- Bring-your-own-key AI with cost estimates and explicit confirmation before every billable call.
- Direct signed uploads and downloads that keep files out of the serverless functions.
- Classic poster and video composed in the browser (MP4 in Edge and Chrome, WebM in Firefox).
- PostgreSQL 17 with integration tests against a real server.
- `third-party-notices.txt` with the licenses of everything served to the browser, generated and
  checked on every build.

## Upgrade and deployment notes

- Database: apply all migrations with `pnpm --filter api db:migrate` (`prisma migrate deploy`)
  before serving this version. They are additive.
- The web app needs the `/api/*` rewrite to the API project added to `apps/web/vercel.json` at
  deployment time.
- The first OWNER is created with `scripts/promote-owner.ts`; there are no default accounts.

## Known limitations

- Not deployed; Vercel, Neon and Blob behaviour (CORS and Range of signed URLs, quotas, client IP
  for rate limiting) is pending verification on the platform.
- No AI provider has been called with a real key.
- Tested on desktop Edge, Chrome and Firefox; not tested in Safari or on physical mobile devices.
- `pnpm audit --prod` reports one remaining high advisory, in `deepmerge-ts` 7, used only by the
  Prisma CLI configuration loader at generate and migrate time; it is not reachable from requests
  and needs an upstream Prisma update.
- The privacy and terms pages are drafts for the future service.
